# Boxing dataset acquisition audit — September 2026

Checked 2026-09-26, with a focused update on 2026-09-27. This supplements [the earlier evaluation plan](data-and-evaluation.md). It records availability and suitability, not permission to use every listed source. CoachMe's public JSON labels/schema, README and license were acquired for local inspection; no external footage, restricted dataset, or model weights were downloaded; no access forms were submitted or authors contacted.

**Recommendation:** prioritize a varied external boxing action corpus and a separate skilled-reference/counterexample collection. Personal webcam rounds provide target-domain development and held-out tests; they do not define correct technique. BoxingWeb now has an official download lead; BoxingVI and ShadowPunch remain useful candidates with access/terms gaps. CoachMe adds published straight-punch correction annotations. CMU motion capture remains auxiliary. The [revised collection plan](expert-reference-data.md) assigns these sources distinct roles; none independently establishes reliable laptop boxing critique.

The factual, machine-readable [catalog](../../ml/datasets/catalog-2026-09.json) records source URLs, modality, label semantics, license status and import blockers. Unknown terms are explicit; a public repository or an article's Creative Commons license does not establish a dataset license.

The September 27 public BoxingWeb listing exposes one 5,190,972,710-byte `boxingweb.rar`, with no separate small video/annotation sample. Listing/provenance were retained locally; the archive was not downloaded. Public availability is now verified, while package contents and training terms remain unverified.

## The new sources, inspected beyond their abstracts

### FightFlow: real metadata, insufficient rights and evaluation

[FightFlow](https://github.com/krishmula/fightflow) exposes 7,980 annotation rows and 3,320 balanced selected clips from 20 videos. Its CSV columns are `video_id,frame_index,punch_type,occluded,notes,timestamp`; `timestamp` contains ISO datetimes rather than video presentation times. Labels are `straight,hook,uppercut,none`, without physical hand. The manifests contain `train=2625,val=695`, while the README calls the latter test. Training has 18 videos; evaluation has just two. Video IDs do not overlap; person separation remains unverified.

The README reports Pose-LSTM F1 .682 and selects the 11-frame window using test F1. That window includes four post-peak frames and uses a bidirectional LSTM. Consequently this is neither untouched test evidence nor causal inference. Metadata inspection also found five video/frame keys assigned conflicting families, requiring adjudication. No LICENSE is present and the GitHub API returns `license:null`; source-video records include YouTube downloads. Public CSVs and a download script do not grant media reuse rights. [Annotation CSV](https://github.com/krishmula/fightflow/blob/main/data/annotations.csv), [manifest](https://github.com/krishmula/fightflow/blob/main/data/processed/dataset_manifest.csv), [repository metadata](https://api.github.com/repos/krishmula/fightflow).

### ShadowPunch: particularly relevant, not yet obtainable in this audit

[ShadowPunch: Fast Actions Spotting Benchmark](https://openreview.net/pdf?id=Jq8HYNZG9s) describes 27 high-definition shadowboxing videos, 230,502 frames at 60 fps, 4,840 event annotations and 4,761 frames with 17-keypoint poses. It separates `straight/hook/uppercut`, physical `left/right`, and `no-punch`. Events mark maximum hand extension, **not onset/end intervals**. This is a promising match for fast-punch and hand-identity work.

The accessible indexed version is anonymous and marked under review for ICLR 2025. Its “open dataset” description was not accompanied by a verified downloadable release, repository, author identity or data license in this audit. Direct OpenReview access requested browser verification; no restriction was bypassed. Status remains **release unverified**, not “available for training.” If obtained, retain point-event semantics and add stance labels before deriving lead/rear classes. Never fabricate action boundaries from fixed windows around those points.

### DuoBox: identified, but the actual dataset terms are restrictive

The other suggested OpenReview ID, `mm0cqJ2O3f`, is [Ready-to-React: Online Reaction Policy for Two-Character Interaction Generation](https://arxiv.org/html/2502.20370v1), accepted at ICLR 2025. Its DuoBox collection has three boxing enthusiasts, 63.4 minutes at 120 fps and 116 sequences: simple movements, combinations and sparring. The movement inventory includes all six punches and defensive actions. This is motion-generation research, not a webcam recognition benchmark.

The [author repository](https://github.com/zju3dv/ready_to_react) describes OptiTrack joint positions/rotations and SMPL-X fits, not released per-punch boundaries, RGB footage or technical-fault labels. Its [dataset request form](https://docs.google.com/forms/d/e/1FAIpQLSe8-G1PxykPoCR0wjH4HZKXkWz3_5UTa9x1if3L7bGPUXhmNA/viewform) limits use to noncommercial research and prohibits further copying, publishing or distributing any portion. Access is revocable. The separate [code license](https://github.com/zju3dv/ready_to_react/blob/main/LICENSE) is PRL v1.0, with registration requirements for organizational project use; it does not replace the dataset agreement. No agreement was accepted. Motion descriptions alone do not give six-class event supervision, and SMPL-X use also needs its own applicable terms checked.

### CMU: a concrete reusable auxiliary source

CMU's [homepage](https://mocap.cs.cmu.edu/) allows including motion data in commercial products while prohibiting direct resale, including converted data. Its [FAQ](https://mocap.cs.cmu.edu/faqs.php) permits copying, modification and redistribution. The [subject 13](https://mocap.cs.cmu.edu/search.php?subjectnumber=13), [subject 14](https://mocap.cs.cmu.edu/search.php?subjectnumber=14) and [subject 17](https://mocap.cs.cmu.edu/search.php?subjectnumber=17) indexes verify boxing trials `13_17,13_18,14_01,14_02,14_03,17_10` at 120 fps. Subjects 13/14 also contain reaching, waving, drinking and household gestures useful as non-punch candidates.

Use targeted original ASF/AMC or C3D files, preserve attribution and do not crawl the site. These are sequence-level “boxing” descriptions, not six-punch event labels. CMU warns that one person may have multiple subject IDs, hand/toe joints can be noisy, and finger/thumb motion is not captured. Manually annotated motion can support synthetic projections and geometry stress tests; it cannot reproduce image occlusion, motion blur or pose-estimator mistakes. Keep projections of one capture in one split and exclude synthetic results from real-webcam accuracy reports.

### Other verified releases and gaps

- [Zenodo Boxing punch data](https://zenodo.org/records/14965635): six CSVs, approximately 11.4 MB, wrist IMU at 200 Hz. The [record API](https://zenodo.org/api/records/14965635) explicitly says open access and `cc-by-4.0`. Files distinguish lead/rear jab, hook and uppercut. The [paper](https://doi.org/10.1371/journal.pone.0322490) describes synchronized video used for annotation, but the published record lists only IMU files. Do not treat the article's video collection as a released RGB dataset.
- [Combat Sports](https://zenodo.org/records/15349809): 7,757 YOLO-labeled images and a 391 MB archive, with classes `boxing-bag,cross,high-guard,hook,kick,low-guard,person`. The [API](https://zenodo.org/api/records/15349809) says CC BY 4.0; the description says Public Domain. Resolve this conflict and source-image provenance. Augmented still images lack event timing, anatomical hands, uppercuts and independent continuous background.
- [Olympic Boxing Punch Classification](https://www.kaggle.com/datasets/piotrstefaskiue/olympic-boxing-punch-classification-video-dataset): the [author metadata endpoint](https://www.kaggle.com/api/v1/datasets/view/piotrstefaskiue/olympic-boxing-punch-classification-video-dataset) verifies a roughly 3.34 GB release and limits use to noncommercial academic teaching/research and nonprofit research organizations. Its eight categories combine physical hand with head/body hit, block or miss. They are not the six punch trajectories. A derivative Hugging Face page cannot broaden the original terms.
- [BoxingVI](https://github.com/Bikudebug/BoxingVI) still offers the closest six-punch interval annotations and estimated COCO poses, but no dataset license was verified. Its 18-athlete/20-video identity mapping needs audit. A [third-party copy's notice](https://github.com/leonardosm14/boxe.ml/blob/main/dataset/NOTICES.md) attributes BoxingVI; that copy's code license is not evidence that BoxingVI data rights were cleared.
- [BoxMAC](https://arxiv.org/html/2412.18204v1) covers six punches plus defenses/background, but image-level labels can combine two boxers; its official release remains unverified. **September 27 update:** [BoxingWeb's author repository](https://github.com/gouba2333/BoxingWeb) links a [public Tsinghua share](https://cloud.tsinghua.edu.cn/d/c435311fecda4566ae76/) and documents MP4, poses and event JSON. Its loader exposes hand, punch family, interval, target, range and effectiveness. The README refers to a LICENSE that is absent from the inspected tree; original-media terms and package contents remain unverified. BoxingStudio is not separately verified as released. Match effectiveness is not form correctness.
- [CoachMe BX](https://github.com/MotionXperts/MotionExpert) now has a pinned local JSON audit: 163 training entries and 41 test entries, covering jabs/crosses with three original and three augmented comments per entry. Published pose/reference pickles are listed, but raw RGB is absent from the inspected dataset directory. See [the detailed acquisition note](expert-reference-data.md) for scope and limits.

## Adoption path for six punches and useful critique

1. **Start with a rights-cleared core.** Preserve complete consented rounds, original video timestamps, person/session/day grouping and frozen annotations. Include hooks and uppercuts at several comfortable ranges, both hands, natural combinations and non-punch gestures. Capture both stances across the eventual cohort. Do not turn drill instructions into labels or require exaggerated “bad technique.”
2. **Clear the strongest external sources before spending on training.** For BoxingVI, obtain dataset/annotation/pose terms, source-media rights, file manifest and athlete mapping. For ShadowPunch, locate the actual release and license first. For DuoBox, decide whether a separate noncommercial research branch is worthwhile; its agreement is incompatible with freely redistributing the training corpus. No outreach or contractual acceptance is implied by this plan.
3. **Use a common import contract without inventing labels.** Preserve `source_id`, checksum, original event semantics, original frame index and presentation timestamp; `family=straight|hook|uppercut`, `physical_hand=left|right|unknown`, `role=lead|rear|unknown`, stance interval, visibility and label provenance. Map a straight to jab/cross only with known lead/rear role. Keep point, clip and interval labels distinct. A no-punch point does not certify all surrounding time as negative; unlabeled time is unknown unless annotation completeness is established. The current annotation schema already supports punch family and physical hand; six-class predicted events and external point/clip adapters still require explicit versioned extensions.
4. **Adapt representations, then measure transfer.** A small causal pose model can learn family/hand timing, with confidence and missingness masks; compare it with a bounded-latency RGB/pose offline model when clear source pixels contradict poses. Never infer measured pose confidence from clean mocap. Use external data for training/development and keep the real webcam test separate. Report continuous one-to-one event matching, physical hand, class confusion, false events/minute, coverage and latency; point-label datasets additionally need their own fixed peak-tolerance protocol.
5. **Collect a separate technique rubric.** A detected hook is not proof of a correct hook. Obtain coach-adjudicated observable criteria, evidence intervals, acceptable variants and `unobservable` labels. Add independent reviewer agreement and assess cue precision before speaking corrections. Force, impact, wrist safety and unseen joint rotation cannot be established merely from a punch class or a clean 3D animation.

The first outside-data experiment should answer whether a source improves hooks/uppercuts on unseen real sessions without increasing gesture false positives. It should not claim generalization from more clips of the same people, or replace an untouched webcam test with a balanced clip-classification score.
