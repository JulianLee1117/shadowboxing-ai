# Optimization update — 26 September 2026

**Recommendation: fix and measure event logic first; compare pose models second; train a small temporal recognizer only after collecting independent labeled sessions.** Faster inference, newer weights, and more landmarks solve different problems. None automatically establishes punch recognition or correct technique.

This supplements [pose models](pose-models.md) and [data/evaluation](data-and-evaluation.md), rather than replacing their broader survey. The sources below were inspected directly; alternative repositories were not installed or benchmarked in this audit. No private recording details or pilot scores are included here.

1. **Separate event failures from tracking failures.** Replay identical saved landmarks through pinned detector versions. Audit extension/turnaround/recovery independently, avoid requiring a fast punch to remain at maximum extension, and evaluate same-hand combinations. Compare recall gains with false events during guard changes, reaches, hooks, and idle movement. A saved-tracking recheck cannot correct missing or wrongly assigned landmarks.
2. **Use the existing capture budget before replacing the pipeline.** At 30 distinct frames/second, observations are approximately 33 ms apart; a narrow peak may occupy one sample. Faster inference does not create additional camera frames, and interpolation is not additional evidence. Measure source cadence, processed cadence, gaps, frame age, and inference separately. Google recommends workers because its browser pose calls are synchronous. [MediaPipe Web guide](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)
3. **Run a targeted pose comparison on identical video frames.** Compare Full with Heavy first, then one challenger. Judge wrists/elbows, physical-hand assignment, dropout duration, and resulting event matches. Include fast combinations and a partly hidden arm. Pose-plus-hand evidence is a testable hypothesis; hidden fists remain unobserved. Do not lower visibility thresholds or silently swap hand identities simply to increase counts.
4. **Learn temporal patterns only after the evaluation exists.** A small causal TCN over normalized coordinates, confidence/missingness, actual time deltas, and motion features is a reasonable next experiment. Use separate arm heads and an unknown/background outcome. Past context need not impose future-frame delay, but boundary confirmation still can. Two development recordings cannot establish a trained model's generalization.

Repository activity dates came from the public GitHub repository API on the review date; activity and stars are not accuracy evidence. The boxing demo's confidence-based praise is specifically unsuitable as a technique assessment rubric.

For a reproducible comparison, freeze video hashes, timestamped event labels, physical hand, visibility/ambiguity labels, detector commit, model hashes, and preprocessing. Keep development recordings separate from a new held-out session. Report one-to-one event precision/recall, duplicate/false events, timing error, identity errors, tracking coverage, and sustained frame age. A new model must improve the difficult cases without hiding extra false positives or discarding uncertain intervals. Apply the master plan's release gates; these experiments do not establish form-critique validity.
